## 1. What P2-A did

P2-A promoted the raw people evidence in `data/durable/store.db` into a canonical,
evidence-first People + Positions layer through **one** new builder and **no** schema
change:

| Artifact | Change |
| --- | --- |
| `scripts/build-people-module.ts` | NEW — the single canonical builder (evidence → projection → store) |
| `src/data/people.ts` | REGENERATED from the durable store (was a stale pilot-DB snapshot) |
| `lk.db` `people` + `positions` | SEEDED (canonical materialisation; derived store) |
| `scripts/smoke-people-p2a.ts` | NEW — 32 acceptance checks |
| `package.json` | `build:people`, `smoke:people-p2a`; chained into `durable:build` |
| `schema/schema.sql` | **UNCHANGED** — no new table, no migration |

The runtime contract is unchanged: `src/data/people.ts` stays a generated evidence
snapshot and `lib/repository/projection.ts` stays the only projection. `PersonDto`
is frozen. The builder reseeds `lk.db` `people`/`positions` from that same projection,
so a person page, the API and the canonical store cannot disagree.

**Why a rebuild was required.** The committed `src/data/people.ts` was generated by
`scripts/pilot-export-people.ts` from a pilot run DB and **no build script ever
regenerated it**. Meanwhile the merged durable store carries *raw* people assertions
from older parser passes that never ran the v2 plausibility gate or the staff-directory
classifier. Reading that store without re-applying those frozen rules would have
published staff rosters and navigation labels as leadership.

## 3. Provenance

Every published person and position carries provenance, enforced by the projection
and asserted by the smoke test:

- `institution_id` / `institution_slug` are **canonical registry** identities
  (`mfi-*`), never the pilot `entity_id`.
- `meta.source` is the owning source; `meta.sources` is every distinct source that
  currently asserts the person (corroboration); `meta.source_url` is the source's
  registered page when one is known, else `null` (never fabricated).
- `meta.last_verified_at` is the latest `observed_at` for that person's evidence.
- Positions carry the role title and `shared_by` (how many people the institution
  lists in the same role field), so a multi-holder role reads as what the source said.

**Institution identity rule.** The pilot `mfi-0NN` `entity_id` and the public registry
both number from 1 but disagree on rows (pilot `mfi-045` = Swastik; registry `mfi-045`
= Nyadi), and the durable store's own `sources.publisher` is often the literal
`"mfi-045"`. So identity is resolved from the **source** (`source_id` →
`data/pilot/pilot-sources.json` publisher → `src/data/institutions.ts`), exactly as the
registry intends. **0 sources were unresolvable**; unresolved sources would be dropped,
not guessed.

## 4. Tenure and history

The evidence holds no appointment or end dates for people. P2-A therefore records
**none**: every seeded `positions.appointed_at` and `positions.ended_at` is `NULL`,
every position is `is_current = 1`, and no history row is invented. "Since" is exposed
in the read model only as the earliest `observed_at` of the current evidence — an
observation date, never claimed as an appointment date. Capture day remains unknown
and is not fabricated (`docs/data/TIMELINE-PROVENANCE.md`).

## 5. Conflicts

The store contains **229 `OPEN` `people_ceo` conflict rows — all SAME-SOURCE**
(`source_a_id = source_b_id`): a single page listing several names under one "CEO"
heading, which is a multi-holder role, not a contradiction. The projection models
that as `shared_by`, not as `CONFLICT`.

- **Cross-source conflicts published: 0.** The builder only emits a conflict key when
  `source_a_id <> source_b_id`. None exist in the current store.
- Same-source multi-holder is *preserved as evidence* and surfaced as `shared_by`,
  never silently resolved. 134 published people sit in a shared role slot (boards
  routinely list several directors).
- No conflict was silently resolved, merged, or deleted.

---

## 5b. Conservative matching / identity

- A person is a distinct `(institution_id, asserted name)`; the key includes the
  institution, so an identical name at two institutions is **never** merged.
- No merging on similar names, and no person is inferred from an institution name or
  a job title.
- Honorific variants of the same person (e.g. `Ram Bahadur Yadav` vs
  `Mr Ram Bahadur Yadav`) are **deliberately not merged** in P2-A: name-similarity
  alone is not sufficient evidence of identity, and merging would be the
  uncontrolled-duplicate error in the other direction. They remain distinct,
  evidence-backed records.

---

## 5a. Position model

Positions use the frozen role-family vocabulary already in the codebase
(`people_chair`/`people_ceo`/`people_director`/`people_board` →
Chairperson / Chief Executive Officer / Director / Board Member). No role was invented,
no title was collapsed, and no job title (e.g. "Divisional Manager", "Head of IT
Department") was promoted to a person — those are held in evidence.

  `entity_id` and registry disagree; `sources.publisher` is often a placeholder).
  P2-A works around this by resolving identity from the real publisher in
  `pilot-sources.json`. Documented, not silently trusted.
- **Honorific-variant duplicates** remain distinct by conservative choice (see §5a).
- **No appointment/tenure dates** exist in evidence; tenure stays `NULL` until a
  source states one.
